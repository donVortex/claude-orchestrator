# Project rules

This project keeps its rules in `.claude/orchestrator/`. Before you change code here:

1. Read `.claude/orchestrator/domain.md`. Its rules are binding, like a brief's. If one contradicts `CLAUDE.md` or the code, follow `CLAUDE.md` or the code and say so.
2. Read the always-check items of the project's review checklist (`.claude/orchestrator/review-checklist.md`, or the checklist file the folder's README names) and check your change against them before you finish.

These files are maintained through reviewed pull requests; edit them by hand if something is wrong. This skill only points to them: never copy rules into it.
